# write4adhd-writing：平实写作

写**交付型文档**：调研报告、实验报告、工作总结、备忘、技术说明。读者要的是"看完就知道发生了什么、结论是什么、下一步干什么"，不是"读得津津有味"——花活是 `write4adhd-book` 的事，这里一概不做。

目标一句话：**让没耐心的人只扫加粗和小标题也能拿到全部重点，让有耐心的人也不用在废话里找重点。**

## 和 write4adhd-book 的分工

本 skill 是基础层，`write4adhd-book` 装在它之上，职责不重叠：

- **本 skill 管"怎么把话写平实、怎么写短"**：说人话、结论先行、抓重点、ADHD 友好的排版硬规则。
- **`write4adhd-book` 管"科普书的形式与花活"**：贯穿性土味比喻、每章收束句、术语三步法、对话式推进、HTML/书站模板与制作规范。

用户要的是面向零基础读者的科普介绍类文章或分章科普书 → 改用 `write4adhd-book`（它动笔前会要求完整读本 skill，找不到就停下来告诉用户补装）。

## 工作流程

1. **明确三件事**（用户没说就先问或按默认推断）：
   - 这份文档替谁解决什么问题（默认：给上级/同事/未来的自己看的一份事实与结论）；
   - 读者读完必须带走的**一两件事**是什么——写不出来就先别动笔，说明重点没抓到；
   - 输出形式：默认 Markdown 文件；用户点名要其他形式（如 HTML）才换。
2. **动笔前必读** `references/plain-style.md`——文风是本 skill 的灵魂，逐条对照执行。
3. **先骨架后正文**：先写 TL;DR（开头一段话或不超过 3 条，结论先行）、各级小标题、每节要给出的关键数字与事实，再扩成正文；骨架立不住就回第 1 步重想重点。
4. 写作时持续做**减法**：支线信息一句带过或挪进附录；拿不准有没有用的段落，默认删。
5. 写完后按 `references/plain-style.md` 末尾的**自查清单**逐条检查。

## 不可妥协的四条底线

1. **说人话**：黑话翻译成大白话，不用术语解释术语；读者不一定认识的概念第一次出现就给一句大白话。
2. **短**：句子短、段落短（连续纯文字不超过 4 行）、篇幅克制；超了就切小标题、改列表、加粗关键词。
3. **抓重点**：结论先行，笔墨按重要性分配，不平均用力；删掉一切"事无巨细"的冲动。
4. **不装权威**：没把握的结论直接标注置信度或写"尚未确认"，给出查证入口，不装斩钉截铁。

输出语言：优先遵循全局指令（如 AGENTS.md、系统提示）中明确的语言要求（如有）；没有的话，与用户提示词所用的语言保持一致。
